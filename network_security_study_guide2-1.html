// 01 — Network Regions & Boundaries

The Three Network Regions

  • Internet The external, untrusted global network. All traffic from here is considered potentially hostile.
  • Intranet The internal, trusted private network — file servers, mail servers, user machines, internal DNS.
  • DMZ Demilitarized Zone — a semi-trusted buffer zone hosting publicly accessible servers (web, mail forwarding, external DNS).

Network Boundaries

  • Firewall — filters packets between regions based on rules.
  • Proxy — an intermediary that makes requests on behalf of clients, adding separation and control.

Dual-Firewall DMZ Architecture

  • Outer firewall — between internet and DMZ; allows only public traffic (HTTP, SMTP) into the DMZ.
  • Inner firewall — between DMZ and intranet; second line of defence.
  • DMZ contains: Web Server, Mail Forwarding, DNS (external).
  • Intranet contains: File Server, Web Server, Mail Server, DNS (internal), User machines.
Key idea: The DMZ ensures publicly accessible services cannot directly reach the internal network. Even if a DMZ host is compromised, the attacker still faces the inner firewall.
// 02 — Packet Filtering

What a Packet Filter Inspects

Uses transport-layer information only:

  • IP Source Address & Destination Address
  • Protocol (TCP, UDP, ICMP, etc.)
  • TCP or UDP source & destination ports
  • TCP Flags (SYN, ACK, FIN, RST, PSH, etc.)
  • ICMP message type

Port Numbering

  • Server ports: below 1024 (permanently assigned)
  • Client ports: 1024–16383 (dynamically assigned)
20/21FTP
23Telnet
25SMTP (send email)
53DNS
80HTTP
110POP3
143IMAP
443HTTPS

Stateless vs Stateful Filtering

Stateless: Ports >1024 must stay open for client replies — a weakness, as any attacker can target those high ports.

Stateful: Firewall remembers outgoing requests. Incoming high-port traffic only allowed if an internal machine initiated an outgoing request on a corresponding low port.

Packet Filtering Issues

  • Stateful filtering — basic filters lack session awareness
  • Encapsulation — address translation (NAT) creates complications
  • Fragmentation — fragmented packets can bypass port-based rules

Packet Fragmentation Attack

Firewall blocks port 23 but allows port 25:

  • Packet 1: Offset=0, MF=1, Dest Port=25 → firewall allows it
  • Packet 2: Offset=1 (overwrites first packet), MF=0, Dest Port=23 → firewall ignores TCP header (treats as data fragment) → passes through
  • Result: Host reassembles packets; traffic arrives at port 23 — rule bypassed!
// 03 — Types of Firewall
TypeHow it WorksSecurity
1. Packet FilterExamines IP/TCP headers, routes packets, applies allow/deny rules per packet.Low
2. Circuit-level ProxyTerminates incoming TCP connections, re-creates new connection to server if allowed.Low–Med
3. Stateful Packet FilterTracks TCP state (SYN/ACK). Rules in one direction only; replies handled automatically.Med–High
4. Application-level ProxyFull client+server per protocol. Validates every request at application layer.High

Packet Filter

  • Rules specify allowed/dropped packets in both directions
  • Rules use source/destination IP and TCP/UDP ports
  • FTP very difficult to support securely
  • Low security

Circuit-level Proxy

  • Packets are NOT routed — proxy terminates them
  • Allowed connections generate a new connection from firewall to server
  • Client never connects directly to server
  • Low–Medium security

Stateful Packet Filter

  • Understands SYN, SYN-ACK, ACK handshake
  • Rules only need one direction (client→server); replies auto-allowed
  • Supports FTP, IRC, H.323
  • Medium–High security

Application-level Proxy

  • Full server & client implementation per protocol (HTTP, FTP, SMTP proxies)
  • Can scan SMTP email for viruses (understands MIME, Zip)
  • Flexible but introduces network delays
  • High security

Telephone Analogy

Packet/circuit/stateful filters = telephone call-barring by number (block/allow by who is calling).

Application proxy = listening to the conversation — but conversations may be encoded or in a foreign language (encryption).

// 04 — Firewall Use, Configuration & ASA

What Firewalls Do

  • Control traffic to/from the protected network
  • Allow or block access to services (internal and external)
  • Enforce authentication before allowing service access
  • Monitor network traffic
  • Restrict internal users from certain external services (security, productivity, cost)

Two Configuration Approaches

1. Allow all, block some (blocklist) — easy to make mistakes; forgotten rules stay open; less secure.

2. Block all, allow some (allowlist) — much more secure; forgotten rules cause complaints. Recommended.

Typical Firewall Ruleset

  • Allow internal → internet: HTTP, FTP, SSH, DNS
  • Allow reply packets
  • Allow anywhere → Mail server: TCP port 25 only
  • Allow Mail server → internet: SMTP, DNS
  • Allow inside → Mail server: SMTP, POP3
  • Block everything else

Problems Firewalls Create

  • Some services break because they are blocked — users complain
  • Network diagnostics may be harder
  • NAT can cause confusion
  • Some protocols are hard to support: FTP, IRC, H.323

ASA Firewall Modes

  • Routed Mode Layer 3 — acts as NAT boundary, separate IPs per interface.
  • Transparent Mode Layer 2 — "bump in the wire" / stealth firewall, no NAT, existing IPs unchanged.

// 05 — Limitations, Bypasses & What Firewalls Can't Do

No Content-Based Filtering (Packet Filters)

  • Email allowed → virus-infected emails also allowed
  • Web access allowed → malicious websites accessible
  • Web access for browser → also enabled for worms like Nimda

HTTP Tunnelling Problem

More services now use TCP port 80 (HTTP) — not just web pages. This makes it hard for firewalls to distinguish legitimate web traffic from tunnelled applications.

Encryption Challenge

  • HTTPS and SSH traffic cannot be inspected or filtered
  • SSH/TLS are end-to-end — no middlebox can decode the payload
  • Encryption is growing (privacy, e-commerce)

Firewall Bypass Methods

  • Direct plugin / external link — traffic not through firewall cannot be blocked
  • Poor configuration — overly permissive rules (e.g. allow all on port 53)
  • Inbound/outbound asymmetry — outbound-initiated connections work both ways
  • Protocol tunnelling — wrapping a blocked protocol inside an allowed one

Core Limitations Summary

  • IP spoofing — router cannot verify true packet origin
  • Multiple app gateways — each protocol needs its own proxy; clients must be configured
  • All-or-nothing UDP — filters often can only fully allow or block UDP
  • Security vs. connectivity trade-off
  • Many highly protected sites still suffer attacks
Key principle: A firewall is one layer of defence-in-depth, not a silver bullet.

// 01 — Network Intrusion: The 5 Stages
Networks must be able to instantly recognise and mitigate threats. Understanding how attackers operate is the foundation of intrusion detection.

Stage 1 — Reconnaissance

Scan the network to:

  • Locate which IP addresses are in use
  • Identify what operating system is running
  • Discover which TCP or UDP ports are "open"
Tool: nmap Example: nmap -sS -P0 -vv -p 21,22,25,110,443 209.162.185.100

Stage 2 — Access

Run "Exploit" scripts against open ports identified during reconnaissance.

Stage 3 — Elevate

Elevate privileges to "root" or "admin" privileges on the compromised system.

Stage 4 — Root Kit

Crackers gain free access without being noticed by auditing. Achieved via a root kit or simple backdoor. Log files (/var/log/secure on Linux, Event Viewer on Windows, Console on Mac) would otherwise expose login activity.

Stage 5 — Utilize

Use IRC (Internet Relay Chat) to invite more hackers, conduct ID theft, Warez distribution, or recruit machines into a Botnet.

nmap Scan Output — What it Reveals

  • filtered — port blocked by firewall (e.g. FTP port 21)
  • open — port is listening (e.g. SSH port 22, HTTPS port 443)
  • Telnet can connect to any port to reveal service banners (e.g. SSH version)
// 02 — IDS vs IPS

Two Generations of Protection

  • IDS — Intrusion Detection System — First generation. Detects and alerts. Operates in promiscuous mode (passive, out-of-band).
  • IPS — Intrusion Prevention System — Second generation. Detects and actively blocks. Operates inline.

Intrusion Prevention Goals

  • Detection
  • Prevention
  • Reaction

IDS — How it Works (Promiscuous Mode)

  • Traffic is mirrored/copied to the IDS sensor (traffic still flows normally)
  • Sensor detects the attack but cannot stop it mid-stream
  • Alerts the management console
  • Attack may still reach the target

IPS — How it Works (Inline Mode)

  • Sensor sits directly in the traffic path
  • Can intercept and drop malicious packets before they reach the target
  • Traffic sent to a "bit bucket" (discarded)
  • Management console is alerted

Comparing IDS and IPS

FeatureIDS (Promiscuous)IPS (Inline)
AdvantagesNo network impact (latency/jitter). Sensor failure has no network impact.Stops trigger packets. Can use stream normalisation techniques.
DisadvantagesCannot stop trigger packets. Needs correct tuning. More vulnerable to evasion.Some latency/jitter introduced. Sensor failure/overload impacts the network.
Key: IDS and IPS are not mutually exclusive — they can complement each other.
// 03 — Detection Methods: Misuse vs Anomaly

Misuse Detection

Compares activity against a database of known attack signatures. Fires when a known bad pattern is matched.

  • Examples: Root password modified while admin not logged in → Misuse
  • UDP packet to port 1434 (SQL Slammer worm) → Misuse

Anomaly Detection

Flags activity that deviates from a learned "normal" profile — can detect unknown attacks.

  • Four failed login attempts → Anomaly
  • Failed connections on 50 sequential ports → Anomaly
  • User logs in at 4:30am from Russian IP → Anomaly

Misuse or Anomaly? Classification

ScenarioType
Root password modified, admin not logged inMisuse
Four failed login attemptsAnomaly
Failed connections on 50 sequential portsAnomaly
User logs in at 4:30am from Russian IP (normally 10am)Anomaly
UDP packet to port 1434Misuse
"DEBUG" in the body of an SMTP messageNot an attack (most likely)

IDS Detection Methods: Practical

  • Use IDS to detect crackers during the scanning stage → lock out the IP address
  • Use a program like TripWire on each host to detect when system files are altered → email alert
// 04 — Signatures

What is a Signature?

A signature is a set of rules that an IDS and an IPS use to detect typical intrusive activity. As new threats are identified, new signatures must be created and uploaded to an IPS.

Signature Attributes

  • Signature Type
    • Atomic One packet required
    • Composite Many packets required
  • Trigger (alarm) — what causes the signature to fire
  • Action — what the IPS does when triggered

Atomic Signature

  • Triggered by a single packet — no state required
  • Example: LAN attack with spoofed TCP SYN where target IP is both source and destination — causes machine to reply to itself continuously

Composite (Stateful) Signature

  • Requires multiple packets
  • Identifies a sequence of operations
  • Usually requires several pieces of data to match

Signature Examples

Pattern-Based Detection

Example atomic: ARP request with source Ethernet FF:FF:FF:FF:FF:FF. Example composite: Searching for "confidential" across multiple packets in a TCP session.

Anomaly-Based Detection

Example atomic: Traffic going to a destination port not in the normal profile. Example composite: Verifying protocol compliance for HTTP traffic.

Policy-Based Detection

Behaviour-based detection where the administrator defines allowed/disallowed behaviours.

Honey Pot-Based Detection

  • Provides a window to view attacks
  • Distracts and confuses attackers
  • Slows down and averts attacks
  • Collects information about attack techniques
  • Requirement: Dedicated honey pot server that must not be trusted

// 01 — AAA: Authentication, Authorization, Accounting

The Three A's

  • Authentication — the process of verifying the digital identity of an entity. Proves who you are.
  • Authorization — determines what an authenticated user is allowed to do.
  • Accounting — keeps track of who did what.

Authentication Modes

  • Local AAA Authentication — credentials are stored on the local device (router/switch).
  • Server-Based AAA Authentication — credentials are managed by a central AAA server (e.g. RADIUS, TACACS+).

Why Centralised AAA?

  • Single point of administration for many users and many devices
  • Consistent policy enforcement
  • Easier to audit who did what (accounting)
  • Easier credential rotation and revocation
// 02 — Four Factors of Authentication

Prove Who You Are

FactorExamples
What you knowPasswords; answers to questions only you know
Where you areIP address, geolocation
What you areBiometrics (fingerprints, iris, voice)
What you haveSecure tokens, mobile devices

Strengthening Passwords

  • Transformed passwords
  • Time stamps
  • One-time passwords
  • Zero-knowledge techniques
  • Digital signatures
  • Personal tokens
  • Add biometrics; graphical passwords
A real-world example: To read mail securely the user might log in to a laptop, log in to a firewall to set up an SSH tunnel, and authenticate to a mail server — typing passwords three times. Less patient users disable the security.
// 03 — Password-Based Authentication: Threats

Why Passwords Fail

In 2012, 76% of network intrusions exploited weak or stolen credentials (username/password). 8 out of 9 exploits involve password stealing and/or cracking. (Verizon Data Breach Investigations Report)

Common Cracking Methods

  • Crack 1: Run dictionary attack
  • Crack 2: Install sniffer or keylogger to steal passwords
  • Crack 3: Run cracking tools on password files
  • Shoulder surfing
  • Same password at multiple sites
  • Broken implementations
  • Social engineering

Real-World Statistics

  • Klein (1990) / Spafford (1992): 2.7% guessed in 15 minutes, 21% in a week
  • U. Michigan: 5% of passwords were "goblue"
  • Zviran & Haga (1999) at DoD California: 80% of passwords were 4–7 characters, 80% alphabetic only, 80% of users never changed their password

Famous Hacks

  • Gary McKinnon (2001–2002): Scottish hacker into 97 US military/NASA computers using a Perl script looking for blank/default admin passwords
  • Rockyou (2009): 32 million passwords leaked via SQL injection
  • Sarah Palin's email: Reset password by guessing date-of-birth, ZIP code, and "where did you meet your spouse?" answers
  • Twitter / Hacker Croll (2009): Took over an employee's Hotmail account via password reset, used old emails to learn original password, then reused on Google Apps, AT&T, Amazon, iTunes

Weak "Reset Password" Questions

  • Make of your first car? — Until 1998 Ford had >25% of market
  • First name of your best friend? — 10% of males: James/Jim, John, Robert
  • Name of first pet? — Max, Jake, Buddy, Bear; Top-500 covers 65%
  • Information is widely available on Facebook etc.
// 04 — Biometrics

Biometric Advantages

  • Nothing to remember
  • Passive — nothing to type, no devices to carry
  • Can't share (usually)
  • Can be fairly unique if measurements are sufficiently accurate

Problems with Biometrics

  • Private, but not secret — biometric passports, fingerprints/DNA left on objects
  • Even random-looking biometrics may not be unique enough — birthday paradox
  • Potentially forgeable
  • Revocation is difficult or impossible
  • Face recognition error rates up to 20% with reasonable variations in lighting, viewpoint and expression

Common Biometric Methods

MethodNotes
FingerprintsTraditional. 1911: first US conviction on fingerprint evidence. UK requires 16-point match (1 in 10 billion false match). Fingerprint damage impairs recognition.
Iris scanningVery random, stable through life. 256-byte iris code based on concentric rings. Equal error rate better than 1 in a million.
Hand geometryUsed in nuclear premises entry control, INSPASS (discontinued 2002).
OtherVoice, ear shape, vein pattern, face temperature.

Biometric Attacks

  • Voice cloning — "my voice is my password" — has been successfully spoofed
  • Cloned retina
  • Fingerprints lifted from beer bottles
  • Eye laser scan
  • Play-Doh fingers fool 90% of fingerprint scanners (Clarkson University study). Suggested fix: perspiration measurement to test "liveness".

Alternative Schemes

  • PixelPin — upload a picture and use 3+ points on it as the password
  • Graphical passwords (Passfaces) — but vulnerable to shoulder surfing; non-dictionary text password is the most vulnerable to shoulder surfing per one study
  • Electronic tattoo — emerging concept
  • "The pill" — chip with one switch that uses stomach acids to activate an 18-bit ECG-like signal inside your body
// 05 — Distributed Authentication & Kerberos

The Naïve Solution

Every server knows every user's password.

  • Insecure: break into one server → compromise all users
  • Inefficient: changing password requires contacting every server

Distributed Authentication Goals

  • Security — against attacks by passive eavesdroppers and actively malicious users
  • Transparency — users shouldn't notice authentication taking place; entering a password is OK if done rarely
  • Scalability — large number of users and servers

Kerberos

  • Developed at MIT in the 1980s
  • Project Athena: clusters of publicly available computers for student/faculty use
  • Shared file service — log in anywhere
  • Two-step authentication: prove identity once to obtain a special TGS ticket, then use TGS to get tickets for any network service

Kerberos Threats

  • Ticket hijacking — malicious user may steal another user's service ticket on the same workstation. Network address verification does not help. Servers must verify that the user presenting the ticket is the user to whom the ticket was issued.
  • No server authentication — attacker may misconfigure the network so they receive messages addressed to a legitimate server, capturing private info or denying service. Servers must prove their identity to users.

Kerberos Version 5 Improvements

  • Better user-server authentication — separate subkey per user-server session
  • Authentication via subkeys, not timestamp increments
  • Authentication forwarding (delegation) — servers can access other servers on user's behalf, e.g. tell printer to fetch email
  • Realm hierarchies for inter-realm authentication
  • Explicit integrity checking + standard CBC mode
  • Multiple encryption schemes, not just DES
// 06 — Multiple Administration Domains: X.500 & LDAP

Hierarchical Directories

Problem: many users — we know how to authenticate, but how to administer? Solution: hierarchical directories — X.500, LDAP, Active Directory.

X.500 Standards

  • X.500 — Distributed Directory. Application uses Directory User Agent (DUA) to access a Directory Access Point.
  • X.501 — Directory Information Base
  • X.511 — Directory Operations (Read, Compare, List, Search, Abandon, Modify, Modify DN)
  • X.509 — Authentication (the famous certificate format)
  • X.519 — Protocols (DAP, DSP, DISP, DOP)
  • X.525 — Replication

DSA — Directory System Agent

  • Software that provides the X.500 Directory Service for a portion of the directory information base
  • Generally, each DSA is responsible for the directory information for a single organisation or unit

X.519 Protocols

  • Directory Access Protocol (DAP) — Request/response from DUA to DSA
  • Directory System Protocol (DSP) — Request/response between DSAs
  • Directory Information Shadowing Protocol (DISP) — DSA-DSA with shadowing agreement
  • Directory Operational binding management Protocol (DOP) — Administrative info between DSAs

LDAP — Lightweight Directory Access Protocol

  • X.500 is too complex for many applications → LDAP is a simplified version
  • Widely used for Internet services
  • Application-level protocol, uses TCP
  • Lookups and updates can use strings instead of OSI encoding
  • Use master servers and replica servers for performance

Example LDAP implementations: Active Directory (Windows/Server), Novell Directory Services, Linux/Unix, iPlanet (Netscape).

Typical uses: user profiles, access privileges, network resources.

// 01 — IP & IPsec Overview

Why IP is Not Secure

  • Content (Payload) is not encrypted — confidentiality is not provided; IP sniffers are freely available
  • IP addresses may be spoofed — authentication based on IP addresses can be broken
  • IP is an unreliable protocol — datagrams may be lost or arrive out of order (TCP handles those)
  • IP is implemented in every end host and router

IPsec — What it Provides

  • General IP Security mechanisms
  • Authentication and confidentiality at IP level
  • Key management features
  • Not bound to any specific encryption/authentication algorithm or keying technology
  • A framework — flexible yet thorough standards for security
  • Protects and authenticates IP packets between source and destination
  • Can protect virtually all traffic from Layer 4 through Layer 7
  • Defined by IETF (RFC 2401–2412)

Main Components of IPsec

  • Confidentiality — using encryption
  • Integrity — using hashing algorithms
  • Authentication — using Internet Key Exchange (IKE) with PSK (Pre-Shared Key) or RSA
  • Secure key exchange — using the Diffie-Hellman (DH) algorithm

IPsec Capabilities Supported

  • Access control
  • Authentication
  • Data encryption
  • Data integrity
  • Nonrepudiation

Works at Layer 3 (Network), can encrypt an entire TCP/IP packet, originally for IPv6, provides authentication before data is transmitted.

// 02 — AH and ESP Protocols

Authentication Header (AH)

  • Achieves authenticity by applying a keyed one-way hash function to the packet to create a hash / message digest
  • The hash is combined with the text and transmitted in plaintext
  • Provides sender authentication and integrity for packet contents and IP header
  • Sender and receiver must share a secret key

Encapsulating Security Payload (ESP)

  • Provides confidentiality by encrypting the payload
  • Can also provide integrity and authentication (MD5 or SHA)
  • When both authentication and encryption are selected, encryption is performed first

AH Header Fields

  • Next header (e.g. TCP)
  • Payload length, Reserved
  • Security Parameters Index (SPI) — identifies the security association
  • Sequence number — for anti-replay
  • ICV (Integrity Check Value) — HMAC of IP header, AH, TCP payload — authenticates source and verifies integrity

The IPsec Framework

IPsec = AH + ESP + IPcomp + IKE:

  • Protection for IP traffic
  • AH — integrity and origin authentication
  • ESP — also confidentiality
  • IPcomp — compression
  • IKE — sets up keys and algorithms for AH and ESP
Building block: The IPsec protocol is the first building block. The choice of AH or ESP establishes which other building blocks are available.
// 03 — Transport vs Tunnel Mode

Two IPsec Modes

  • Transport mode — host to host or host to gateway. Usually within the same network. Secures packet payload, leaves the original IP header unchanged. Used between hosts.
  • Tunnel mode — gateway to gateway or host to gateway. Encapsulates both IP header and payload into IPSec packets (IP-in-IP encryption). Used in remote-access and site-to-site implementations.

Transport Mode Layout

[IP header (real dest)] [IPSec header] [TCP/UDP header + data]

Security is provided only for the Transport Layer and above. Protects the payload but leaves the original IP address in plaintext.

Tunnel Mode Layout

[New IP header (gateway)] [IPSec header] [Original IP header (real dest)] [TCP/UDP header + data]

Tunnel mode provides security for the complete original IP packet. The original IP packet is encrypted and encapsulated in another IP packet.

When to Use Each

Use CaseMode
Two hosts on the same network needing end-to-end protectionTransport
Site-to-site VPN between corporate routersTunnel
Remote-access user dialling into a corporate gatewayTunnel
Host to gateway in the same organisationEither
// 04 — Security Association (SA) & IKE

What an SA Defines

  • One-way sender–recipient relationship
  • Determines how packets are processed
  • Cryptographic algorithms, keys, IVs, lifetimes, sequence numbers, mode (transport or tunnel)
  • Uniquely identified by SPI (Security Parameters Index)
  • Each IPsec device keeps a database of SAs
  • SPI is sent with the packet, telling the recipient which SA to use
  • Plus destination IP address and protocol identifier (AH or ESP)

SA Contents

  • Protocol used (AH, ESP)
  • Mode (transport, tunnel)
  • Encryption or hashing algorithm
  • Negotiated keys and key lifetimes
  • Lifetime of this SA

Internet Key Exchange (IKE)

  • Goal: establish security association for AH and ESP
  • If IKE is broken, AH and ESP provide no protection
  • IKE Phase 1 — establishes a secure channel between peers
  • IKE Phase 2 — negotiates the IPsec SAs that will protect user data

IPsec VPN Negotiation Steps

  • Step 1: Host A sends "interesting" traffic to Host B
  • Step 2: R1 and R2 negotiate an IKE Phase 1 session
  • Step 3: R1 and R2 negotiate an IKE Phase 2 session
  • Step 4: Information is exchanged via IPsec tunnel
  • Step 5: The IPsec tunnel is terminated
// 05 — VPN, SSL/TLS, HTTPS

What is a VPN?

  • Virtual Private Network — secure connection over a public network
  • Benefits: Cost Savings, Security, Scalability, Compatibility

VPN Topologies

  • Remote-Access VPNs — typically enabled dynamically by the user. Created using either IPsec or SSL. Two flavours: clientless VPN (browser-based, SSL/TLS) and client-based VPN.
  • Site-to-Site IPsec VPNs — VPN gateway encapsulates and encrypts outbound traffic, sends through a tunnel over the internet to a VPN gateway at the target site. Receiving gateway strips headers, decrypts, relays to target host. Typically secured using IPsec.

SSL / TLS

  • SSL/TLS sits above the TCP Socket — it is part of the Application Layer (a "shim")
  • TLS = Transport Layer Security (this is NOT "IPsec Transport Level Security")
  • TLS is used for email (SMTP/TLS, POP/TLS, IMAP/TLS)
  • SSL is used for secure web access (HTTPS, now uses TLS v.3), Secure Shell (SSH), Secure Copy (SCP), Secure File Transfer (SFTP)

HTTPS

  • Port: 443

// 06 — MPLS (Multi-Protocol Label Switching)

What is MPLS?

  • IETF standard, currently defined only for IP
  • An MPLS path acts as a tunnel — from an MPLS ingress point to an egress point
  • Arranged between Layer 2 and Layer 3
  • Idea: combine the forwarding algorithm of ATM with IP

Motivation: IP vs ATM Trade-offs

ProtocolProsCons
IPFirst defined; de facto only protocol for global internetworkingConnectionless (no QoS); each router makes independent forwarding decisions; large IP header (≥20 bytes); routing at network layer is slower than switching; shortest-path bias
ATMConnection-oriented (supports QoS); fast switching with fixed-length cells; integrates voice/data/videoComplex, expensive, not widely adopted

MPLS Components

  • Label Edge Router (LER) — at the edge of the MPLS network. Assigns and removes labels. Supports multiple ports to dissimilar networks (frame relay, ATM, Ethernet).
  • Label Switching Router (LSR) — high-speed router in the core. ATM switches can be used as LSRs without hardware change.
  • Forward Equivalence Class (FEC) — a group of packets that share the same transport requirements. Assignment done once when the packet enters the network.
  • Label-Switched Path (LSP) — established before transmission. A path is a representation of an FEC. Unidirectional — return traffic needs another LSP.
  • Label Distribution Protocol (LDP) — distributes label bindings to LSRs.

The Label

  • Exp field — conveys class of service (like IP precedence bits)
  • S (BS) field — when BS=1, the current label is on the bottom of the stack; multiple labels can form a stack
  • TTL field — 8-bit time to live; if 0, packet expired and won't be labelled

LSP Setup Options

  • Hop-by-hop routing — each LSR independently selects the next hop for a given FEC (OSPF, ATM)
  • Explicit routing — similar to source routing; the ingress LSR specifies the full list of nodes

MPLS Operation — Five Steps

  1. Label creation and distribution — routers bind labels to FECs and build their tables (LDP, downstream-initiated)
  2. Table creation — each LSR creates entries in the Label Information Base (LIB) mapping input port + input label → output port + output label
  3. Label-switched path creation — LSPs created in the reverse direction to LIB entries
  4. Label insertion / table-lookup — first router (LER1) finds next hop and requests a label. Subsequent routers just use the label. Egress LSR (LER4) removes the label and delivers the packet.
  5. Packet forwarding — labels swapped at each hop; LER4 strips the label and delivers

LDP Message Types

  • Discovery — announce and maintain LSR presence
  • Session — establish, maintain, terminate LDP sessions
  • Advertisement — create, change, delete label mappings for FECs
  • Notification — advisory info and error signalling

MPLS Traffic Engineering

  • Inherent in MPLS via explicit routes
  • RSVP-TE — request bandwidth and traffic conditions; drawback: regular refreshes, scalability
  • CR-LDP — uses link characteristics (bandwidth, delay), hop count, QoS; drawback: more complexity in routing calculation

MPLS Pros and Cons

Advantages: improves packet-forwarding performance; supports QoS / CoS for service differentiation; scalable; integrates IP and ATM; interoperable.

Disadvantages: adds another layer; routers must understand MPLS.

MPLS VPN Components

  • CE router — Customer Edge
  • PE router — Provider Edge
  • P router — Provider (core)
  • ASBR router — Autonomous System Border Router

MPLS VPNs can use iBGP or eBGP between PEs and CEs to exchange routes.

// 01 — Auditing Basics

What is Auditing?

The term audit comes from the Latin word "audire" — meaning "to hear". Authenticity of accounts is assured with the help of an independent review.

Auditing is an intelligent and critical examination that exhibits an accurate and fair view of the state of affairs.

Purpose of Auditing

Audit is performed to ascertain:

  • The validity and reliability of the Security Policy and its enforcement
  • To detect and prevent error and fraud
  • To check the effectiveness of security systems

IT Audit Goals

Auditing involves a systematic evaluation of an organisation's IT infrastructure to detect high-risk activities, threats, and vulnerabilities. It ensures that security measures are in place to protect against cyberattacks.

  • Reviewing security policies — ensuring alignment with industry standards
  • Evaluating security practices — checking if security protocols are followed
  • Assessing risk management — identifying potential threats and their impact

Security Policy — Topics to Cover

  • Who can use resources
  • Proper use of the resources
  • Granting access & use
  • System administrator privileges
  • User rights & responsibilities
  • What to do with sensitive information
  • Desired security configurations of systems

Audit Outputs

  • Describe security state
  • Evaluate effectiveness of protection mechanisms

Logging = recording of system events and actions. Analysis of log records = auditing. Then acting on the findings.

// 02 — Types of Auditing

Process Audit

  • Verifies that processes are working within established limits
  • Evaluates an operation or method against security policy
  • Measures conformance to security policy and effectiveness of security systems
  • Examines resources (equipment, materials, people), the environment, methods (procedures, instructions), and measures collected
  • Checks adequacy and effectiveness of process controls established by procedures, instructions, flowcharts, training and process specifications

Product Audit

  • An examination of a particular security product or service — such as hardware, software, or servers
  • Evaluates whether it conforms to security requirements

System Audit

  • An audit conducted on a management system
  • A documented activity performed to verify, by examination and evaluation of objective evidence, that applicable elements of the system are appropriate and effective
  • Confirms elements have been developed, documented, and implemented in accordance with specified requirements

// 05 — SNMP (Simple Network Management Protocol)

What SNMP Does

  • Monitor, diagnose, and manage networks
  • Monitor performance and overall state of devices (active, inactive, partially operational, network gridlocked, etc.)
  • Detect problems and manage exceptional events (loss of a network link, equipment ceasing to function)
  • Configure equipment
  • Works on the application layer — UDP port 162

SNMP Key Elements

  • Management station
  • Management agent
  • Management Information Base (MIB)
  • Network Management Protocol — Get, Set, Notify

SNMP Components Explained

  • The SNMP Manager — host running the SNMP management software (usually a computer used to monitor the network)
  • The SNMP Agent — software running on a network device (router, switch, server) allowing it to be monitored
  • The Management Information Base (MIB) — set of object collections managed by the SNMP agent. Each collection has variables that may be consulted or modified by the SNMP manager.

SNMP Versions

  • SNMPv1 — "connectionless" since it uses UDP
  • SNMPv2 — allows the use of TCP for "reliable, connection-oriented" service. Adds GetBulkRequest and InformRequest.
  • SNMPv3 — adds security capability to be used with v1 or v2 (USM, VACM)

// 06 — SNMPv3 Security & Models

SNMPv1 Community Facility

  • SNMP Community — relationship between an SNMP agent and SNMP managers
  • Three aspects of agent control:
    • Authentication service
    • Access policy
    • Proxy service

SNMPv3

SNMPv3 defines a security capability to be used in conjunction with SNMPv1 or v2 — it does not replace them, it secures them.

User Security Model (USM)

USM is designed to secure against:

  • Modification of information
  • Masquerade
  • Message stream modification
  • Disclosure

NOT intended to secure against:

  • Denial of Service (DoS attack)
  • Traffic analysis

View-Based Access Control Model (VACM)

VACM has two characteristics:

  • Determines whether access to a managed object should be allowed
  • Makes use of an MIB that:
    • Defines the access control policy for this agent
    • Makes it possible for remote configuration to be used
Trap: an unsolicited message from an agent reporting an alarm condition. v1 uses UDP (connectionless); v2 supports TCP (reliable, connection-oriented).

// 03 — WEP (Wired Equivalent Privacy)

First Generation Wireless Security

  • Service Set Identifier (SSID)
  • Media access control (MAC) filtering
  • Neither option was secure — e.g. wireless sniffing reveals both
  • AP can be set to "Do NOT allow any SSID"

WEP Basics

  • IEEE 802.11 WEP standard specified a 40-bit key
  • Most vendors extended WEP to 128 bits or more
  • Based on RC4 (Rivest Cipher 4)
  • Part of the IEEE 802.11 specification
  • Goal: as secure as a wired LAN

WEP Services

  • Access control
  • Message confidentiality
  • Message integrity

WEP Access Control — Challenge/Response

  1. Client → AP: authenticate request
  2. AP → Client: authenticate challenge (r) — r is 128 bits long
  3. Client → AP: authenticate response (eK(r))
  4. AP → Client: authenticate success/failure

WEP Keys

Two kinds of keys:

  • Default key — also called shared key, group key, multicast key, broadcast key
  • Key mapping keys — also called individual key, per-station key, unique key
  • In practice, often only default keys are supported

WEP Flaws

  • Authentication is one-way only
  • The same shared secret key is used for both authentication and encryption
  • No session key is established during authentication
  • Access control is not continuous
  • Replay of client messages is still possible

WEP Attacks

  • Bit Flipping
  • Replay Attacks
  • Weak IV collection — utility called AirSnort captures weak Initialization Vectors to determine the WEP key
// 04 — Authentication and Association

802.11 Authentication Methods

The 802.11 standard defines two methods for clients to connect to an access point:

  • Open Authentication
  • Shared Key Authentication

Three connection elements:

  • Probe
  • Authentication
  • Association

Open Authentication

Open-system authentication is really "no authentication".

  • The client:
    • Sets Authentication Algorithm Number to 0 (open-system)
    • Sets Authentication Transaction Sequence Number to 1
  • The AP:
    • Sets Authentication Algorithm Number to 0 (open-system)
    • Sets Authentication Transaction Sequence Number to 2
    • Status Code set to 0 (Successful)

Key point: Authentication and data encryption are two different things.

Shared-Key Authentication

  • Shared-key authentication uses WEP
  • Can only be used on products that support WEP
  • WEP is an encryption algorithm, not a method of authentication
  • Shared-key authentication makes use of WEP, so can only be used on APs and clients that implement WEP

The Authentication Framework

  • Probe → Authentication → Association
  • Open authentication = no authentication (just association)
  • Shared-key requires the client to encrypt a challenge with the shared WEP key
  • Subsequent secure standards (WPA, WPA2, 802.11i) replace this with strong mutual authentication
// 05 — WPA & WPA2

Secure 802.11 WLANs: WPA

  • WLAN industry recognised the vulnerabilities of 802.11 authentication and data privacy
  • WEP is not safe
  • Wi-Fi Alliance → Wi-Fi Protected Access (WPA)
  • Also called Simple Secure Networking (SSN)

WPA vs WEP — Key Improvements

  • Access control model based on 802.1X
  • Flexible authentication framework (based on EAP)
  • Authentication can be based on strong protocols (e.g. TLS)
  • Authentication process results in a shared session key (prevents session hijacking)
  • Different functions (encryption, integrity) use different keys derived from the session key using a one-way function
  • Integrity protection is improved
  • Encryption function is improved
  • Improved payload integrity

TKIP and Data Privacy

One major improvement in WPA over WEP is the Temporal Key Integrity Protocol (TKIP). TKIP dynamically changes keys as the system is used — defeating well-known key recovery attacks on WEP.

Key enhancements with TKIP:

  • Per-frame keying — WEP key quickly changed on a per-frame basis
  • Message Integrity Check (MIC) — effective data-frame integrity
  • Solves statistical attacks such as AirSnort and the IV vulnerability
  • Changes WEP key before an attacker can collect enough frames to derive key bytes

WPA Modes

  • Pre-shared Key (PSK) Mode
    • Does not require authentication server
    • "Shared Secret" is used for authentication to access point
  • Enterprise Mode
    • Requires an authentication server
    • Uses RADIUS
    • Centralises management of user credentials

WPA Features & Migration

  • 802.1x; BSS; Key Hierarchy; Key Management; Cipher & Authentication Negotiation
  • Data Privacy Protocol: TKIP
  • Software/firmware upgrade to existing APs and NICs
  • Inexpensive in time and cost to implement; vendor-compatible
  • Suitable for different user types
  • Runs in enterprise mode or PSK mode

Migration:

  • Existing authentication systems can still be used
  • WPS replaces WEP
  • All APs and clients need new firmware and drivers
  • Some older NICs and APs may not be upgradeable

WPA2 & AES

  • Uses Advanced Encryption Standard (AES)
  • AES selected by NIST as replacement for DES
  • Symmetric-key block cipher using 128-bit keys
  • Generates CCM Protocol (CCMP):
    • CCMP = CTR + CBC + MAC
    • CTR = Counter Mode Encryption
    • CBC = Cipher Block Chaining
    • MAC = Message Authentication Code

WPA vs 802.11i

  • 802.1x; BSS; Independent Basic Service Set; Pre-authentication
  • Key Hierarchy; Key Management; Cipher & Authentication Negotiation
  • Data Privacy Protocol: TKIP and CCMP
Bottom line: WEP is insufficient. WPA is a dramatic improvement. WPA2 provides even stronger security but needs significant upgrades, including hardware change.
// 06 — 802.1X, EAP, WLC

Key Terms

  • EAP (Extensible Authentication Protocol) — RFC 3748
  • EAPOL (EAP over LAN) — 802.1X
  • RADIUS (Remote Access Dial-In User Service) — RFC 2865-2869, RFC 2548. Carries EAP messages between the AP and the auth server. Mandated by WPA.
  • LEAP (Light EAP) — Cisco proprietary, similar to MS-CHAP
  • EAP-TLS — only the TLS Handshake Protocol is used. Server and client authentication, generation of master secret. TLS master secret becomes the session key. Mandated by WPA, optional in RSN.
  • PEAP (Protected EAP) — Phase 1: TLS Handshake without client auth; Phase 2: client auth protected by the secure channel from phase 1
  • EAP-SIM — extends GSM authentication in Wi-Fi

802.1X

  • Provides mutual authentication
  • Any client without built-in 802.1X must use a software supplicant
  • The client must have some proof of identity
  • Used with a RADIUS Server Manager

WLAN Controller (WLC) — Why?

  • Channel assignments
  • AP power management
  • Handling of roaming-related functions
  • Rogue detection & mitigation (WIPS)
  • Centralised management; coordinated control of APs and clients
  • Richer, coordinated set of services across hundreds or thousands of APs

Thin (Lightweight) APs vs Fat (Autonomous) APs

AspectThin APFat AP
Code on APMinimal — just enough to reach the networkFull operating code and config
ConfigurationProvided by WLCIndividually configured
CoordinationCoordinated centrallyNo coordination with other APs
Best forLarge networks via single admin pointVery small networks / niche applications (bridge links)

WLC Planes & Topologies

  • Management Plane
  • Control Plane — provides dynamic services & changes settings dynamically (e.g. roaming)
  • Data Plane — actual physical and logical path taken by user traffic

WLC Form factors: Dedicated hardware (1U/2U); Dual-role APs; Virtualised (VMware, ESXi, Cisco vWLC); Cloud-based (e.g. Meraki); Unified Access (WLC functionality in a switch).

Cloud-Based WLC

Pros: Easy to administer via one central entity; global view of the WLAN.

Cons: Single point of failure; ongoing support and software updating; possible licensing impact.

Other WLC Features

  • Guest portal — "coffee shop" Wi-Fi experience; web login page; self sign-up or reception-created credentials
  • WIPS — Wireless IPS / IDS built in to WLC. Monitors and contains rogue devices.
  • Bonjour services (Apple); traffic filtering; rate limiting; packet inspection / policy decisions; QoS marking; gathering AP data; Chromecast support

AP Tunnels

When using a controller, APs build a tunnel back to the WLC. WLC cannot discover the AP — the AP has to "call home" and form a Layer 3 connection back to the WLC. Cisco's vWLC is software that runs on a hardware-compatible virtualisation infrastructure (e.g. VMware, ESX, ESXi 4.x & 5.x).
