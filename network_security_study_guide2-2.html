// 01 — Network Regions & Boundaries

The Three Network Regions

  • Internet The external, untrusted global network. All traffic from here is considered potentially hostile.
  • Intranet The internal, trusted private network — file servers, mail servers, user machines, internal DNS.
  • DMZ Demilitarized Zone — a semi-trusted buffer zone hosting publicly accessible servers (web, mail forwarding, external DNS) isolated from the intranet.

Network Boundaries

  • Firewall — filters packets between regions based on rules.
  • Proxy — an intermediary that makes requests on behalf of clients, adding separation and control.

Dual-Firewall DMZ Architecture

  • Outer firewall — between internet and DMZ; allows only public traffic (HTTP, SMTP) into the DMZ.
  • Inner firewall — between DMZ and intranet; second line of defence. Compromise of a DMZ server does not mean compromise of the intranet.
  • DMZ contains: Web Server, Mail Forwarding, DNS (external).
  • Intranet contains: File Server, Web Server, Mail Server, DNS (internal), User machines.
Key idea: The DMZ ensures publicly accessible services cannot directly reach the internal network. Even if a DMZ host is compromised, the attacker still faces the inner firewall.
// 02 — Packet Filtering

What a Packet Filter Inspects

Uses transport-layer information only:

  • IP Source Address & Destination Address
  • Protocol (TCP, UDP, ICMP, etc.)
  • TCP or UDP source & destination ports
  • TCP Flags (SYN, ACK, FIN, RST, PSH, etc.)
  • ICMP message type

Port Numbering

  • Server ports: below 1024 (permanently assigned)
  • Client ports: 1024–16383 (dynamically assigned)
20/21FTP
23Telnet
25SMTP (send email)
53DNS
80HTTP
110POP3
143IMAP
443HTTPS

Stateless vs Stateful Filtering

Stateless: Ports >1024 must stay open for client replies — a weakness, as any attacker can target those high ports.

Stateful: Firewall remembers outgoing requests. Incoming high-port traffic only allowed if an internal machine initiated an outgoing request on a corresponding low port.

Packet Filtering Issues

  • Stateful filtering — basic filters lack session awareness
  • Encapsulation — address translation (NAT) and tunnelling create complications
  • Fragmentation — fragmented packets can bypass port-based rules

Packet Fragmentation Attack

Firewall blocks port 23 but allows port 25:

  • Packet 1: Offset=0, MF=1, Dest Port=25 → firewall allows it
  • Packet 2: Offset=1 (overwrites first packet), MF=0, Dest Port=23 → firewall ignores TCP header (treats as data fragment) → passes through
  • Result: Host reassembles packets; traffic arrives at port 23 — rule bypassed!
// 03 — Types of Firewall
TypeHow it WorksSecurity
1. Packet FilterExamines IP/TCP headers, routes packets, applies allow/deny rules per packet.Low
2. Circuit-level ProxyTerminates incoming TCP connections, re-creates new connection to server if allowed.Low–Med
3. Stateful Packet FilterTracks TCP state (SYN/ACK). Rules in one direction only; replies handled automatically.Med–High
4. Application-level ProxyFull client+server per protocol. Validates every request at application layer.High

Packet Filter

  • Rules specify allowed/dropped packets in both directions
  • Rules use source/destination IP and TCP/UDP ports
  • FTP very difficult to support securely
  • Low security

Circuit-level Proxy

  • Packets are NOT routed — proxy terminates them
  • Allowed connections generate a new connection from firewall to server
  • Client never connects directly to server
  • Low–Medium security

Stateful Packet Filter

  • Understands SYN, SYN-ACK, ACK handshake
  • Rules only need one direction (client→server); replies auto-allowed
  • Supports FTP, IRC, H.323
  • Medium–High security

Application-level Proxy

  • Full server & client implementation per protocol (HTTP, FTP, SMTP proxies)
  • Flow: Client → Firewall (validates) → Firewall → Server → back through Firewall
  • Can scan SMTP email for viruses (understands MIME, Zip)
  • Flexible but introduces network delays
  • High security

Telephone Analogy

Packet/circuit/stateful filters = telephone call-barring by number (block/allow by who is calling).

Application proxy = listening to the conversation — but conversations may be encoded or in a foreign language (encryption).

// 04 — Firewall Use, Configuration & ASA

What Firewalls Do

  • Control traffic to/from the protected network
  • Allow or block access to services (internal and external)
  • Enforce authentication before allowing service access
  • Monitor network traffic
  • Restrict internal users from certain external services (security, productivity, cost)

Two Configuration Approaches

1. Allow all, block some (blocklist) — easy to make mistakes; forgotten rules stay open; less secure.

2. Block all, allow some (allowlist) — much more secure; forgotten rules cause complaints so you notice and fix them. Recommended.

Typical Firewall Ruleset

  • Allow internal → internet: HTTP, FTP, SSH, DNS
  • Allow reply packets
  • Allow anywhere → Mail server: TCP port 25 only
  • Allow Mail server → internet: SMTP, DNS
  • Allow inside → Mail server: SMTP, POP3
  • Block everything else

Problems Firewalls Create

  • Some services break because they are blocked — users complain
  • Network diagnostics may be harder
  • NAT can cause confusion
  • Some protocols are hard to support: FTP, IRC, H.323

ASA Firewall Modes

  • Routed Mode Layer 3 — acts as NAT boundary, separate IPs per interface.
  • Transparent Mode Layer 2 — "bump in the wire" / stealth firewall, no NAT, existing IPs unchanged.

ASA CLI Modes

  • ciscoasa> — User EXEC mode
  • ciscoasa# — Privileged EXEC (after enable)
  • ciscoasa(config)# — Global config (after configure terminal)
  • ciscoasa(config-if)# — Sub-configuration (interface level)
Key: IOS do command not needed on ASA. Stop show output with Q, not Ctrl+C.

// 05 — Limitations, Bypasses & What Firewalls Can't Do

No Content-Based Filtering (Packet Filters)

  • Email allowed → virus-infected emails also allowed
  • Web access allowed → malicious websites accessible
  • Web access for browser → also enabled for worms like Nimda

HTTP Tunnelling Problem

More services now use TCP port 80 (HTTP) — not just web pages. This makes it hard for firewalls to distinguish legitimate web traffic from tunnelled applications. Even application proxies may not catch this.

Encryption Challenge

  • HTTPS and SSH traffic cannot be inspected or filtered
  • SSH/TLS are end-to-end — no middlebox can decode the payload
  • Encryption is growing (privacy, e-commerce)
  • Firewalls can see the port but not the content

Firewall Bypass Methods

  • Direct plugin / external link — traffic not passing through firewall cannot be blocked
  • Poor configuration — overly permissive rules (e.g. allowing all traffic on port 53)
  • Inbound/outbound asymmetry — outbound-initiated connections work both ways
  • Protocol tunnelling — wrapping a blocked protocol inside an allowed one

Core Limitations Summary

  • IP spoofing — router cannot verify true packet origin
  • Multiple app gateways — each protocol needs its own proxy; clients must be configured
  • All-or-nothing UDP — filters often can only fully allow or block UDP
  • Security vs. connectivity trade-off — tighter rules mean less usability
  • Many highly protected sites still suffer attacks
Key principle: A firewall is one layer of defence-in-depth, not a silver bullet. Many highly protected sites still suffer successful attacks.
// 06 — Real-World Firewalls

Check Point Firewall

  • Market leader in enterprise firewalls
  • Type: Stateful Packet Filter + some proxy + authentication
  • Cost: ~£10,000s
  • Typically runs under MS Windows (unreliable, low performance, questionable security as host)
  • Alternative platform: Nokia — even more expensive

Symantec Raptor

  • Type: Application Proxy + some packet filtering
  • Cost: ~£10,000s
  • Runs under MS Windows

Cisco PIX / ASA

  • Type: Stateful Packet Filter
  • Cost: ~£1,000s (cheaper than Check Point)
  • High performance
  • Inconvenient command-line user interface

ASA 5505 Hardware

  • 8 built-in switch ports (Fast Ethernet), ports 0–1 PoE capable
  • Supports up to 3 VLANs (Outside, Inside, DMZ)
  • Security Services Card (SSC) expansion slot
  • USB ports, console port, auxiliary port

ASA 5510 Hardware

  • 1 Security Services Module (SSM) slot for IPS/AV
  • 2 USB 2.0 ports, out-of-band (OOB) management interface
  • 4 Fast Ethernet interfaces
  • Flash card slot, serial console port, auxiliary port
  • LEDs: Power, Status, Active, VPN, Flash

ASA Deployment Scenarios

  • Small Branch: Single ASA 5505, internet (VLAN 2) + inside (VLAN 1) — workstations, printer, IP phones
  • Small Business: ASA 5505 with 3 VLANs — Outside, DMZ (web server), Inside
  • Enterprise: Central corporate ASA + remote branch ASA 5505s connected via IPsec VPN over internet

// 01 — Network Intrusion: The 5 Stages
Networks must be able to instantly recognise and mitigate threats. Understanding how attackers operate is the foundation of intrusion detection.

Stage 1 — Reconnaissance

Scan the network to:

  • Locate which IP addresses are in use
  • Identify what operating system is running
  • Discover which TCP or UDP ports are "open" (being listened to by servers)
Tool: nmap Example: nmap -sS -P0 -vv -p 21,22,25,110,443 209.162.185.100

Stage 2 — Access

Run "Exploit" scripts against open ports identified during reconnaissance.

Stage 3 — Elevate

Elevate privileges to "root" or "admin" privileges on the compromised system.

Stage 4 — Root Kit

Crackers gain free access without being noticed by auditing systems. Achieved via a root kit or simple backdoor. Log files (/var/log/secure on Linux, Event Viewer on Windows, Console on Mac) would otherwise expose login activity.

Stage 5 — Utilize

Use IRC (Internet Relay Chat) to invite more hackers, conduct ID theft, Warez distribution, or recruit machines into a Botnet.

nmap Scan Output — What it Reveals

  • filtered — port blocked by firewall (e.g. FTP port 21)
  • open — port is listening (e.g. SSH port 22, HTTPS port 443)
  • Telnet can connect to any port to reveal service banners (e.g. SSH version)
// 02 — IDS vs IPS

Two Generations of Protection

  • IDS — Intrusion Detection System — First generation. Detects and alerts. Operates in promiscuous mode (passive, out-of-band).
  • IPS — Intrusion Prevention System — Second generation. Detects and actively blocks. Operates inline with network traffic.

Intrusion Prevention Goals

  • Detection — identify the intrusion
  • Prevention — stop it before damage
  • Reaction — respond and recover

IDS — How it Works (Promiscuous Mode)

  • Traffic is mirrored/copied to the IDS sensor (traffic still flows normally)
  • Sensor detects the attack but cannot stop it mid-stream
  • Alerts the management console
  • Attack may still reach the target

IPS — How it Works (Inline Mode)

  • Sensor sits directly in the traffic path
  • Can intercept and drop malicious packets before they reach the target
  • Traffic sent to a "bit bucket" (discarded)
  • Management console is alerted

Comparing IDS and IPS

FeatureIDS (Promiscuous)IPS (Inline)
AdvantagesNo network impact (latency/jitter). Sensor failure has no network impact.Stops trigger packets. Can use stream normalisation techniques.
DisadvantagesCannot stop trigger packets. Needs correct tuning. More vulnerable to evasion.Some latency/jitter introduced. Sensor failure/overload impacts the network.
Key: IDS and IPS are not mutually exclusive — they can complement each other. A network-based IPS should be inline to defend against fast-moving worms and viruses.

Network-Based IPS Placement

  • Sensors placed at multiple points: inside corporate network, between corporate network and firewall, in the DMZ area
  • Management server controls all sensors centrally
  • Works alongside web server, DNS server, and the untrusted network boundary

Detection Methods Overview

  • Misuse detection — matches known attack patterns (signatures)
  • Anomaly detection — flags behaviour that deviates from a normal baseline
// 03 — Detection Methods: Misuse vs Anomaly

Misuse Detection

Compares activity against a database of known attack signatures. Fires when a known bad pattern is matched.

  • Examples: Root password modified while admin not logged in → Misuse
  • UDP packet to port 1434 (SQL Slammer worm) → Misuse

Anomaly Detection

Flags activity that deviates from a learned "normal" profile — can detect unknown attacks.

  • Four failed login attempts → Anomaly
  • Failed connections on 50 sequential ports → Anomaly
  • User who normally logs in at 10am from a UK dorm logs in at 4:30am from a Russian IP → Anomaly

Misuse or Anomaly? Classification Table

ScenarioType
Root password modified, admin not logged inMisuse
Four failed login attemptsAnomaly
Failed connections on 50 sequential portsAnomaly
User logs in at 4:30am from Russian IP (normally 10am from UK dorm)Anomaly
UDP packet to port 1434Misuse
"DEBUG" in the body of an SMTP messageNot an attack (most likely)

IDS Detection Methods: Practical

  • Use IDS to detect crackers during the scanning stage → lock out the IP address, or remove malware from a local host
  • Use a program like TripWire on each host to detect when system files are altered → email alert to Sys Admin
The challenge: "DEBUG" in an SMTP message looks suspicious but is a legitimate SMTP command. Not all anomalies are attacks — false positives are a real problem in detection systems.
// 04 — Signatures

What is a Signature?

A signature is a set of rules that an IDS and an IPS use to detect typical intrusive activity. As new threats are identified, new signatures must be created and uploaded to an IPS.

Signature Attributes

  • Signature Type
    • Atomic One packet required to match
    • Composite Many packets required (stateful)
  • Trigger (alarm) — what causes the signature to fire
  • Action — what the IPS does when triggered

Atomic Signature

  • Triggered by a single packet — no state required
  • Example: A LAN attack with a spoofed TCP SYN packet where the IP address of the target is both source and destination — causes the machine to reply to itself continuously
  • Detectable from a single Wireshark capture frame

Composite (Stateful) Signature

  • Requires multiple packets to match the pattern
  • Identifies a sequence of operations
  • Usually requires several pieces of data to match an attack signature

Signature Examples

IDNameDescription
1101Unknown IP ProtocolTriggers when an IP datagram is received with the protocol field set to 134 or greater.
1307TCP Window Size VariationFires when the TCP window varies in a suspect manner.
3002TCP SYN Port SweepTriggers when a series of TCP SYN packets have been sent to many different destination ports on a specific host.
3227WWW HTML Script BugTriggers when an attempt is made to view files above the HTML root directory.

Signature Micro-Engines (SME)

IOS software relies on SMEs to process signatures. Since IOS 12.4(11)T, Cisco introduced version 5.x, an improved IPS signature format.

EngineDescription

Signature OSI Layer Coverage

  • Application/Presentation layers: DNS reconnaissance and DoS, Worms, viruses, Trojan horses, adware, malware
  • Transport layer: Port sweeps, Port scans, TCP SYN attack
  • Network/Data Link layers: Fragmentation attacks, IP options, ICMP reconnaissance and DoS

Key Takeaways — IDS/IPS Summary

  • A network must be able to instantly recognise and mitigate worm and virus threats
  • A network-based IPS should be implemented inline to defend against fast-moving Internet worms and viruses
  • IPS signatures provide the IPS with a list of identified problems
  • Signatures are configured to use various triggers and actions
  • Security staff must continuously monitor an IPS solution and tune signatures as necessary to ensure adequate protection

Cisco Hardware — IPS Integration

  • Cisco ASA 5510 has an SSM (Security Services Module) slot for IPS/AV expansion cards
  • Cisco AIP SSM (Advanced Inspection and Prevention Security Services Module) is a dedicated IPS card
  • Provides hardware-accelerated inline inspection of all traffic
  • Integrated into the ASA firewall appliance
Remember: IDS and IPS are not mutually exclusive — they can and should complement each other in a defence-in-depth strategy alongside firewalls.
